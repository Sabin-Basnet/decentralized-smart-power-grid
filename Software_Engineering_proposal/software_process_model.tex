\section{Software Process Model}

\subsection{Waterfall Model}
The classic linear Waterfall model is selected for this project: Requirements Analysis $\rightarrow$ System Design $\rightarrow$ Implementation $\rightarrow$ Testing $\rightarrow$ Deployment $\rightarrow$ Maintenance.

\subsection{Phases of the Model}
\begin{enumerate}[leftmargin=*]
  \item \textbf{Requirements analysis:} Formulating this comprehensive IEEE 830 SRS document.
  \item \textbf{System design:} Designing database models, pinning Solidity contract states, and detailing circuit schematics.
  \item \textbf{Implementation:} Programming the ESP32 firmware ($C++$), configuring the FastAPI gateway (Python), and launching smart contracts.
  \item \textbf{Testing:} Validating contract transactions, checking relay latency, and quantifying ML forecasting error.
  \item \textbf{Deployment:} Spinning up the infrastructure locally via Hardhat and launching local host environments.
  \item \textbf{Maintenance:} Optimizing smart contract execution costs (gas optimization) and refining ML feature variables.
\end{enumerate}

\subsection{Justification}
\begin{itemize}[leftmargin=*]
  \item The transactional mechanics of prepaid utility metrics are stable and clearly defined.
  \item The dependencies between the physical hardware layer, contract layer, and middleware logic demand a predictable, sequential step-by-step pipeline.
  \item Fixed deadlines for academic checkpoints require highly deterministic progress markers.

\end{itemize}
