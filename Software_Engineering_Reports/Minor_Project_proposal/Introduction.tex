\chapter{INTRODUCTION}
\section{Background}
Electricity distribution systems require reliable measurement, timely payment processing, and rapid identification of unsafe or abnormal consumption. Conventional prepaid systems often depend on a central application to store balances and decide whether a consumer remains connected. This creates a single operational point of failure and makes it difficult to independently verify balance deductions and disconnection decisions.

This project proposes a local prototype of a decentralized prepaid smart power grid. An ESP32-based meter sends consumption and tamper telemetry to a FastAPI backend. The backend validates the meter, records operational history in SQLite, and uses a Solidity smart contract on a local Hardhat network to maintain and deduct prepaid energy credits. A React web dashboard presents the current balance, load, meter status, and system events. A lightweight machine-learning component estimates the remaining service time, while electrical current comparison provides an explainable tamper signal.

\section{Problem Definition}
Small communities and prototype deployments need an affordable way to demonstrate prepaid electricity enforcement without requiring a production utility platform. A purely centralized implementation can hide the source of balance changes, continue operating when its ledger is inconsistent, and provide limited visibility into meter tampering. The problem addressed by this project is therefore the design and validation of an end-to-end prototype that links physical telemetry, transparent prepaid accounting, safety decisions, and human-readable monitoring in one workflow.

\section{Objectives}
\begin{itemize}
  \item To design an ESP32-based smart meter prototype that periodically reports load, energy, current, and tamper status.
  \item To implement a FastAPI service that validates telemetry, stores meter history, and coordinates the grid-control workflow.
  \item To implement a Solidity prepaid ledger that records meter credits and deducts energy consumption transparently.
  \item To provide automatic disconnect decisions when tampering is detected or prepaid credit is depleted.
  \item To estimate remaining operating time from historical consumption and display system status through a React dashboard.
\end{itemize}


\section{Scope of Project}
The project is limited to a working local prototype and simulation environment. It includes ESP32/Wokwi telemetry generation, meter registration and validation, SQLite history, local Hardhat blockchain transactions, prepaid balance deduction, current-differential tamper detection, remaining-hours estimation, and a React web dashboard. The default demonstration account represents a meter in Dharan.

The project does not claim to replace certified utility meters, production blockchain infrastructure, tariff regulation, utility-scale grid protection, or a production security audit. The local blockchain and seeded data are used to evaluate the proposed workflow in a controlled environment.
