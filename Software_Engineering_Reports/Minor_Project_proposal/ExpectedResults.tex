\chapter{EXPECTED RESULTS}
The final prototype is expected to demonstrate an integrated prepaid grid loop. The ESP32/Wokwi node will send JSON telemetry to the FastAPI gateway, which will validate the meter, process the reading, deduct prepaid credit through the local smart contract, and return a relay command. Tampering or depleted credit will produce an isolation decision that the firmware can apply to the simulated load circuit.

The React web dashboard will display current users, load, meter status, balance, telemetry history, tamper alerts, and an estimated number of hours remaining. The estimate will be presented as a forecast rather than an exact guarantee, because actual exhaustion depends on future consumption. Controlled current differences and explicit tamper inputs will generate explainable anomaly alerts.

The framework's final performance will be quantitatively evaluated using four core engineering metrics:
\begin{itemize}

\item Smart Contract Transaction Latency: Time between an accepted telemetry update and local ledger deduction confirmation.

\item Balance Deduction Accuracy: Mathematical precision of contract-executed tariff calculations versus theoretical values.

\item Remaining-Time Forecast Error: The accuracy of the service-time estimate, evaluated using Root Mean Squared Error (RMSE) where labelled test data is available.

\item Tamper Detection Precision: The success rate of the current-differential rule in identifying controlled tamper cases with minimal false alarms.
\end{itemize}
